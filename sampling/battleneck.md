### 적용한 개선 (모델 입력·배치 순서 동일 → 기존 결과와 비교 가능)
1. **조립을 DataLoader 워커로 병렬화** — `05_sampling_train.py`
   - `batch_loader(store, edge_ids, batch, workers)`: 학습 순서(`order`)를 batch 개씩 자른 그대로 워커가 `collate` → 배치 내용·순서는 직렬과 같음
   - fork 로 워커 생성 → memmap 은 페이지 캐시 공유 (워커 수만큼 메모리 안 늘어남), 워커당 torch 스레드 1
   - 학습 루프, 에폭별 검증 `predict`, `--eval-test` 테스트 `predict` 세 곳 모두 적용
   - `--workers` 인자 추가 (기본 4, 0 = 예전 직렬 조립)
2. **조립 벡터화** — `sampling_lib.py`
   - `collate`: target 마다 `build` 를 부르던 루프를 배치 단위 numpy 연산으로. 노드·간선을 (배치 안 target 번호, id) 합성 키로 한꺼번에 정렬·중복 제거 → target 끼리 섞이지 않고, target 안 순서도 `build` 의 `np.unique` 순서와 같음
   - `_select_batch`: 여러 target 의 owner adjacency 행을 한 번에 선택
   - `_rows`: owner 별 `np.arange` 루프 → ragged arange (`_select` 도 이걸 씀, 출력 동일)
   - `collate_ref`: 예전 `collate` (검증용으로 남김), `build`·`_select` 출력 불변
   - 검증: 실제 학습 그래프 배치 50개에서 7개 텐서(x, edge_index, edge_attr, target_index, target_attr, incoming, outgoing) dtype·shape·값 전부 일치

### 검토했지만 하지 않은 것
- **서브그래프 공유(union, Multi-GNN/FraudGT 의 LinkNeighborLoader 방식)**: 이득이 ① 의 13% 뿐인데, 점수가 같은 배치에 든 다른 target 에 따라 달라짐 (재현성·서비스 1건 추론과 불일치), 기존 결과와 비교 불가 → 05 와 별도 실험 (v11 후보)
- **memmap → RAM 적재**: ⑤ 에서 디스크 병목이 아님을 확인해 불필요
- **검증 축소 (`--val-neg-rate` 0.005)**: 지금도 에폭 간 AP 흔들림이 문제라 추정 분산을 키우지 않음. 워커 적용으로 검증도 같이 빨라짐
- **배치 크기 증가·AMP**: 남은 병목(GPU 25 ms)을 줄이지만 학습 결과가 바뀜 → 비교 실험 중엔 하지 않음. 바꾼다면 다음 단계 시작 전에 모든 조건에 똑같이
