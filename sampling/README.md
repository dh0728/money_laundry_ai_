## 태훈님 (GNN통합본)
- 경로 : `money_laundry/docs/02_data/taehoon/이진분류_GNN실험결과/`
- 데이터 : HI-Large, 36피처(노드 19 + 엣지 17), 일별 그래프 + 2홉 문맥
- 분할 : 학습 2022-08-08~09-27, 검증 2022-09-28~10-14, 테스트 미사용(검증셋 결과만 있음)
- 모델 : GNN 6종 (TGNN·GAT·GATv2·GINE·EdgeSAGE·EdgeWeightedGCN) × 3시드
- 적용 기법 : original / random_under / cluster_under(MiniBatchKMeans 32군집, 크기비례 75% + 균등 25% 배분)
  - 샘플링 비율 : 일별 정상의 1% (random·cluster 공통) ≈ 정상:양성 약 10:1
  - 가중치 : 샘플링한 정상에 IPW(N/n) 적용 + 양성 pos_weight=300 → 목적함수는 original과 동일
  - 샘플링 대상은 학습 target 간선만, 그래프·이웃·노드 피처는 전체 유지
- 확인 지표 (검증셋, 3시드 평균·표준편차)
  - AP(PR-AUC) ← 에폭 선택 기준
  - precision / recall / F1 ← 검증 F1 최대 임계값에서 계산
  - accuracy, FPR, ROC-AUC
  - recall@1%(상위 1% 알림 예산에서 재현율), unmatched_recall@1%(패턴 외 세탁 재현율)
- 결과 : original ≥ cluster_under ≈ random_under (AP 0.60~0.61 vs 0.57~0.62). TGNN만 cluster_under 0.621로 최고
- 별도 : 잠재공간 증강 실험 72건(repeat / SMOTE / WGAN-GP, 고정 인코더 위 새 분류기) — 다운샘플링과 다른 절차라 직접 비교 불가

### 태훈님 실험이 결과가 origin이 제일좋거나 비슷했던 이유?
정상을 1%만 남기면서 남긴 정상 하나하나에 100배 가중치(IPW)를 줬다.(1건이 100건의 몫을 하도록) 이걸 손실을 계산할 때는 빼고 거래그래프 자체는 유지된 상태로 해서 
이렇게 하면 평균은 원래와 같이 맞춰지지만 한 건에 의해 전체가 좌우하기 때문에 분산만 커지고 좋아질 수 없고 나빠지는 경우가 더 많음

따라서 이 실험은 정상을 줄여도 성능이 유지되나를 확인 한거지 불균형을 해소 한게 아님

## 은총님 (us_undersample_compare)
- 경로 : `money_laundry/docs/02_data/chong/preprocess and model/model/us_undersample_compare.ipynb`
- 데이터 : HI-Large, 54열 피처(엣지 `amt_z_pay_ccy` 제외), 패턴 밖 세탁 제외
- 분할 : 태훈님 분할 사용, val 33,633,093행 / test 30,390,801행
- 모델 : LightGBM 9클래스 (정상 + 패턴 8종), 10 round마다 val macro-AP로 선택, test 1회 채점
- 적용 기법 : k-means / CLARA k-medoids / CSSMC × r∈{10,30,100,300} × w∈{1,300} + full_w300 = 25게 조건(모델 25개 학습)
  - r : 정상:패턴 비율 (목표 정상 = 패턴 행 × r)
  - w : 패턴 세탁 행 가중치 (w300 = 세탁 300·정상 1)
  - 무작위 없음(일정 간격·중심 근접 순서·시작 오프셋), 시드 반복 없음
  - CSSMC는 k-means 군집을 공유하고 후보 중 KL 최소 subset 선택
- 확인 지표 (test)
  - macro_AP_9 (9클래스 one-vs-rest 평균) ← 1위 판정 기준
  - macro_AP_패턴8종, 세탁여부_AP(1−P(정상) 점수), AP_정상, 세탁여부_argmax_F1
  - 패턴행중_유형정답률
  - ECE_세탁_15구간, Brier_세탁, 확률눈금(예측확률 평균 ÷ 실제 비율)
  - 분포 왜곡 : KL_평균(모집단 ‖ 남긴 정상, 54열 평균), 일별 보존율 범위
  - 비용 : 학습 행 수, 학습 시간, 메모리 피크
- 결과 : cssmc_r300_w300 1위 (macro-AP 0.281, full_w300 0.275 대비 +2.3%, 학습 행 18%, 시간 73분 vs 260분). KL↔성능 스피어만 −0.41. k-means 중심 근접 선택이 KL·일별 편차·확률 눈금 모두 최악

## 현재 샘플링 실험

### 왜 하나
- HI-Large 학습 구간(8/8~9/27) 정상 8,750만 : 세탁 9.4만 = 930 : 1
- 정상 전부로 학습하면 1에폭 69시간(target당 2홉 서브그래프를 만드는 v10 구조라), 양성이 배치에 거의 안 들어와 학습 신호도 희박
- 목표: **성능을 유지하면서 정상을 얼마나·어떻게 줄일 수 있나** + 양성 비중을 바꾸면 성능이 더 오르나

### 방식 — 지도 vs 구조
GNN에서 "정상을 줄인다"는 두 가지가 있다. 같은 선택 목록을 두 방식에 각각 적용해 비교한다.

| | 지도(loss) 샘플링 | 구조(struct) 샘플링 |
|---|---|---|
| 줄이는 것 | 역전파에 참여하는 정상 target 간선 | 메시지 패싱 그래프의 정상 간선 자체 |
| 그래프·이웃·노드 피처 | 그대로 | 이웃이 사라짐 (노드 피처는 유지 = 구조-A) |
| 서비스와의 일치 | 서비스는 CONTEXT를 전체 누적으로 주므로 일치 | train/serve 분포가 어긋날 위험 |
| 역할 | **주 실험** | 대조군 (정말 나쁜지 숫자로 확인) |

#### 서비스와 일치 부분의 추가적인 설명
```
구조 샘플링 학습 그래프 (정상 90% 삭제)
  정상 계좌 : 이웃 평균 5개      ← 정상 거래를 지웠으니 조용해 보임
  세탁 계좌 : 이웃 평균 30개     ← 세탁 거래는 다 남아 있음
  → 모델이 배움: "이웃 많음 = 수상"

추론 그래프 (전체)
  정상 계좌 : 이웃 평균 50개     ← 지운 적 없으니 원래대로 바쁨
  → 모델: "이웃 많네, 수상" → 정상 계좌 전부 오탐
```
예시 처럼 같은 정상 계좌가 학습 때와 추론 때 다르게 보이는 것을 말함


### 분리해서 보는 두 축
- **r (샘플링 비율)** = 정상 : 양성. 일별로 그날 양성 × r 만큼 정상을 남김. 데이터 양·학습 시간·추정 분산을 정함
- **π_eff (양성 손실 비중)** = 손실에서 양성 가중치 합의 비율. `pos_weight`를 여기서 역산해 r과 독립으로 고정
  - 같은 r에서 IPW를 되돌리면(reweight=ipw) 목적함수가 full과 같아짐 (태훈님 방식) → 대조군
  - 되돌리지 않으면(reweight=none) 모델이 보는 비율이 실제로 바뀜 → 불균형 해소 효과


### 방법

#### RUS(Random Under Sampling)
- 일별 층화 무작위 — 그날 양성 × r 건을 무작위로

#### CSSMC
- k-means 군집 비례 후보 여러 개 중 모집단과 KL이 가장 작은 subset

#### 다축 비례 층화 Reservoir Sampling
- 날짜 × 금액 구간 × 최근 거래 횟수 × 은행 간 × 신규 계좌쌍 층을 만들어 모집단 비율대로

#### hard-negative 혼합
- 절반 정도를 **어려운 정상**에서 나머지는 무작위로

- hard-negative의 기준 
  - **세탁 계좌가 낀 정상 거래** — 세탁 거래의 송신·수신 계좌가 한 번이라도 포함된 정상 거래. 세탁 계좌도 평소엔 정상 거래를 하니까, "같은 계좌인데 이건 정상, 저건 세탁"을 구분하려면 이게 필요
  - **같은 분 sibling** — 세탁 거래와 같은 송신 계좌에서 같은 분에 찍힌 정상 거래 (03 리뷰에서 찾은 생성기 특성)

제외: Tomek/ENN/NearMiss 등 kNN 계열(1.8억에서 불가, 경계 정상을 지움), k-means 중심 근접(분포 왜곡)

#### k-means에서 분포가 왜곡된다는 것에 의미
k-means는 군집마다 중심점에 가까운 순서대로 뽀는 건데, 그러면 군집 가장자리(전형적이지 않은 정상)
```
군집 하나의 정상 거래 분포          중심 근접으로 10% 뽑으면
   ·  ·   · · ·   ·  ·                      · · ·
 ·   · · ● ● ● · ·   ·      →            ● ● ●
   ·  ·   · · ·   ·  ·                      · · ·
 (●=중심 근처, ·=가장자리)           가장자리는 하나도 없음
```

이렇게 뽑으면
1. 피처 분포가 쪼그라듬
  - 모집단은 넓게 퍼져 있는데 표본은 중심에 뭉쳐서, 은총님 audit에서 KL이 random의 10배 이상(0.041 vs cssmc 0.000003)으로 나왔었는데 이게 모델이 "정상은 이 좁은 범위"라고 배우고 추론 때 가장자리 정상이 들어오면 세탁으로 오판하기 할 수 있음
2. 경계가 사라짐
  - 세탁과 헷갈리는 정상은 대개 군집 가장자리(고액, 잦은 거래, 신규 계좌)에 있어서 그걸 버리면 모델에게 가장 중요한 경계 사례가 사라짐 
3. 시간 평향
  - 중심 근접 순서가 날짜와 무관하게 정해져서 어떤 날이 많이 남고 어떤 날은 거의 없을 수 있음 
  - 은총님 결과를 보면 k-means 많이 버리는 날과 적게 버리는 날과의 비율이 12배 정도 차이가 남
    - (cssmc 1.05배, clara 2.1배, k-means 12배)
4. 확률눈금 붕괴
  - 정상이 "쉬운 정상"뿐이라 모델이 과신하게 되고, 예측 확률 평균이 실제 비율의 38배 (cssmc 5.5배)
  - **확률 눈금**은 모델이 내는 확률이 실제 비율과 맞냐는 거야 (보정, calibration).
    - cssmc    0.55%  → 실제의 5.5배 
    - k-means  3.8%   → 실제의 38배 
  - k-means로 학습한 모델은 정상 거래에도 "세탁일 확률 몇 %"를 남발해. 순위(AP)와 별개로, 확률 숫자 자체가 못 믿을 값이 될 수 있음


### 평가
- 검증 9/28~10/14, 양성 전부 + 정상 2% 가중 표본(가중치 50)으로 고정, 모든 조건 공유 → 전체 채점의 불편추정
- 지표: AP, F1, recall@1%(알림 예산), 패턴 외 세탁 recall@1%, ECE(확률 보정), 학습 시간·GPU
- 학습 없이 보는 통계(audit): 피처 분포 KL/PSI, 일별 보존율, 시간대 분포, 세탁 계좌 연루 비율, 양성 1홉 보존율
