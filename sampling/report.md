### 비교 조건
- 방식 : random(RUS) · strata 3축(day, amount, cross_bank) · strata 5축(+ recent, new_pair) · hard(hard-negative 50%) · cssmc
- 비율 r : 10 · 30 · 100 (정상 : 양성)

  - `pos` : 그날 양성 수 × r → 날마다 정상:양성 = r:1, 정상이 많은 날은 보존율이 낮음
  - `neg` : 전체 예산 × 그날 정상 수 비율 → 모든 날 보존율이 같음, 날별 정상:양성은 달라짐
  - cssmc 는 군집 크기 비례로 전체 예산을 나눠 날짜를 보지 않음 (사실상 `neg` 와 같은 효과)
- 총 27개 select (cssmc 3 + 나머지 4방식 × 3비율 × 2규칙)

## 해석

1. **분포 차이는 거의 전부 "날짜별 예산 배분"에서 나옴**
   - `pos` 규칙은 정상이 몰린 날(월말 Reinvestment)을 적게 뽑아 날짜 비중이 모집단과 달라짐 → kl_raw 0.0059, 일별 보존 편차 5.69배
   - `neg` 규칙으로 바꾸면 random 도 kl_raw 0.00001, 일별 보존 편차 1.00배로 떨어짐
   - 처음에 cssmc 가 통과한 이유도 군집화가 아니라 날짜를 보지 않고 배분했기 때문

2. **같은 날짜 배분에서는 strata·cssmc 가 random 과 차이 없음**
   - `neg` 규칙에서 random·strata·cssmc 모두 kl_raw 약 0.00001 (표본 크기에서 생기는 최소 오차 수준)
   - 하루 약 2만 건씩 뽑으므로 무작위로도 하루 안의 분포가 이미 정확함 → 층화·군집화로 더 줄일 차이가 없음
   - 통계 선별 표의 "탈락"은 random 대비 비율(0.78~1.06배)로 판정한 결과인데, 값이 0.00001 수준이라 비율 차이는 의미 없음

3. **hard 는 의도대로 동작**
   - 세탁 계좌 연루 비율 0.246 → 0.500, 같은 분 sibling 비율 2배
   - 분포를 일부러 바꾸는 방식이라 kl_raw 가 큰 것이 정상 (`neg` 규칙에서 0.0055 = 순수하게 hard 비율 변화로 생긴 차이)
   - 통계로는 판단할 수 없으므로 학습으로 확인

4. **비율 r 은 분포 보존에 영향 없음** — r10·r30·r100 의 kl_raw 가 같음. r 의 효과는 학습으로만 확인 가능


> 하루에 2만 건 이상 무작위로 뽑으면, 그것만으로 모집단 분포가 거의 정확히 재현돼. 그래서 층화나 군집화로 더 줄일 오차가 남아 있지 않는다. 때문에 이제는 **”모집단을 얼마나 닮았나"**를 재. 그런데 우리가 알고 싶은 건 **”세탁을 구분하는 데 도움이 되는 정상을 남겼나"**를 확인해야 함

## 학습 결과 (GNN v10 구조, 검증 2022-10-03 ~ 10-16)

### 공통 설정
- 모델 : v10 과 같은 층 구성 (TransformerConv 2층, 양방향 메시지, ego 표시), target 마다 2홉 서브그래프 (owner·방향별 이웃 최대 100, hash 고정)
- 학습 : 지도(loss) 샘플링 — 그래프는 전체, 손실에 넣는 정상 target 만 줄임 (struct 1건 제외)
- 손실 가중 : π_eff = 손실에서 양성 가중치 합의 비중. `pos_weight = π/(1−π) × 정상 수 / 양성 수` 로 역산 → r 을 바꿔도 양성 비중은 그대로
- 학습률 2e-3, 배치 32, 최대 6에폭, patience 2 (검증 AP 기준 조기 종료), 최고 AP 에폭의 모델로 지표 기록
- 검증 : 검증 구간 양성 전부(33,795) + 정상 2%(487,587, 가중치 50) — 모든 조건이 같은 표본
- 비교 지표 : AP(주), recall@1%(알림 예산 상위 1% 안에서 잡은 양성 비율), 패턴 외 recall@1%(알려진 8개 패턴 밖의 세탁)
- ECE·threshold 는 비교하지 않음 — 정상을 줄인 만큼 확률이 부풀려져 r·π 마다 기계적으로 달라짐

### struct (구조 샘플링) 관찰
- 학습 그래프에서 선택 안 된 학습 정상 101,119,248건 제거, 검증 그래프는 전체 그대로
- 1에폭 최고(0.463) 후 0.445 → 0.337 로 떨어져 조기 종료 — 학습할수록 성긴 학습 그래프에 맞춰져 전체 그래프(검증·서비스)와 어긋나는 것으로 해석 (직접 확인은 안 함)
- 서비스 추론은 항상 전체 그래프 → struct 는 학습·추론 그래프가 늘 달라 서비스에 부적합
- 노드 피처는 재계산하지 않아(구조-A) "거래 수"는 그대로인데 이웃은 성긴 상태 — 피처까지 재계산하는 구조-B 는 미실행
- recall@1%(0.791)·패턴 외 recall(0.496)은 loss s42 보다 높았지만 시드 1개라 판단 보류

### 결론
1. **샘플링 방식·비율·양성 비중·날짜 예산·적용 위치 어느 것도 시드 흔들림(AP 표준편차 0.04~0.06)보다 큰 차이를 내지 않음**
2. 실무 기본값 : **random r10, loss, π_eff 0.25 (RUS)** — 가장 단순하고 학습 시간이 짧음 (r30 의 1/3). hard 를 써도 비용은 같으나 우월하다는 근거는 없음
3. 지금 가장 큰 문제는 샘플링이 아니라 **학습 불안정** — 같은 데이터에서 시드만 바꿔도 AP 가 0.1 흔들려, 0.05 이하의 차이는 어떤 실험으로도 가려낼 수 없음
4. 검증 AP 0.44 ~ 0.56, F1 0.49 ~ 0.60 — FraudGT 의 HI-Large 테스트 F1(GIN 계열 53 ~ 59)과 같은 범위 (검증 기준이라 참고용)

### hard 방식의 "어려운 정상" 기준 (참고)
- 모델 점수가 아니라 규칙 기반 : 학습 구간 정상 중 ① 세탁 거래에 등장한 계좌가 송신·수신자인 거래, ② 세탁 거래와 같은 송신계좌·같은 분의 거래
- 이 풀이 학습 정상의 24.6% (2,510만 건)로 넓음 → hard 는 "세탁 계좌 주변 정상 비중을 25% → 50% 로 두 배"에 가까움. 효과가 작게 나온 이유일 수 있음
- 모델이 헷갈리는 정상(기준 모델 점수가 높은 정상)을 고르는 방식은 미실행

### 적용 (모델 입력·배치 순서 동일 → 기존 결과와 비교 가능)
- `05_sampling_train.py` : `batch_loader` 로 학습·검증·테스트 조립을 DataLoader 워커(fork, memmap 공유)에서. `--workers` 기본 4 (0 = 직렬)
- `sampling_lib.py` : `collate` 를 배치 단위 numpy 연산으로 (노드·간선을 (target 번호, id) 합성 키로 정렬·중복 제거 → target 끼리 안 섞임). 예전 구현은 `collate_ref` 로 남김

### 결과
- r10 1에폭 73분 → **31 ~ 34분** (2.2 ~ 2.4배), 조건 1개 445분 → 약 155 ~ 200분
- r30 1에폭 176분 → 83분
- 배치당 측정(36 ms)으로 예상한 19분보다 긴 이유 : 실제 학습엔 loss 계산·optimizer step·`loss.item()` 동기화가 더 있음

### 하지 않은 것
- 서브그래프 공유(union, Multi-GNN/FraudGT 의 LinkNeighborLoader 방식) : 이득 13% 뿐, 점수가 같은 배치의 다른 target 에 따라 달라짐(재현성·서비스 1건 추론과 불일치), 기존 결과와 비교 불가
- 배치 크기 증가·AMP : 학습 결과가 바뀌어 비교 실험 중엔 보류
