# 패턴 분류 설계

## 앞에서 확인한 주의 내용

## 1. 구간별 클래스 수

- 데이터가 8/1 에 시작해서 진행 중인 시도가 쌓여 하루 엣지 수가 안정되기까지 시간이 걸린다. GATHER-SCATTER 는 시도가 가장 길어 안정되는 데 가장 오래 걸리고(9월 말~10월 초), UNMATCHED 는 8/1 부터 바로 일정량이 나온다 → 학습 구간 비율로 클래스 가중치를 잡으면 GATHER-SCATTER 가 약간 과보정된다 

- 절대 시각 피처는 빼야 한다. 시기에 따라 클래스 비율이 달라서 "시기 → 클래스" 지름길이 생긴다


- 모든 패턴의 시도가 8/1 부터 하루 약 20개씩 일정하게 시작한다
- BIPARTITE·STACK 의 after(236·230)가 다른 패턴(약 110~140)보다 많다.

- GATHER-SCATTER 는 1,133개 중 277개만 test 에서 시작 → test 에 걸친 시도의 76%가 이전 구간에서 시작했다. 
- 즉 val·test 엣지의 상당수는 "진행 중이던 시도의 뒷부분"이다 → **평가할 때 새로 시작한 시도 / 이어진 시도를 나눠서 봐야 한다**

## 2. 구간 경계에서 잘리는 시도

-  **전체 시도의 52.6%가 둘 이상 구간에 걸친다.** GATHER-SCATTER 70.3%, SCATTER-GATHER 64.4% 로 높고 BIPARTITE 27.6% 로 가장 낮다.

- 걸친 시도는 첫 구간 밖으로 행의 약 60%가 나간다 (GATHER-SCATTER 75%) → 살짝 걸친 게 아니라 크게 나뉜다
- 구간 경계로 시도를 깔끔하게 나누는 분할은 불가능하다 → 분할은 이진 실험과 같게 두고, 평가를 나눠서 해석한다

- **학습 GATHER-SCATTER 엣지 대부분은 학습 그래프(10/2 까지)에서 시도 뒷부분이 안 보인다.**

- 진짜 누수 후보(같은 시도의 엣지가 학습 라벨로 쓰임)는 2-1절 in_train_% 로 따로 본다: test 34.5% (GATHER-SCATTER 64.3%, BIPARTITE 0.7%)

### 2-1. 라벨 겹침(누수 후보)과 성숙도
  - `in_train_%` = 같은 시도가 학습 구간에도 있음(val·test 에서 = 라벨 누수 후보)
  -  `in_val_%` = 같은 시도가 검증 구간에도 있음, `before_%` = 시도가 학습 시작 전에 시작

- test 패턴 엣지 중 같은 시도가 학습 라벨에도 있는 비율(in_train)은 34.5%, test 에서 새로 시작한 시도의 엣지(new)는 30.8%
- 패턴별 차이가 크다: GATHER-SCATTER in_train 64.3% (시도가 가장 김) / BIPARTITE 0.7% (시도가 짧아 학습까지 안 닿음)
- **val 은 in_train 67.9% 로 test(34.5%)보다 훨씬 높다** — val 이 학습 바로 뒤라 같은 시도를 많이 공유한다. 검증 macro-F1 로 모델을 고르면 "같은 시도를 외운" 모델이 유리할 수 있다 → 모델 선택 때 val 의 new 묶음 지표도 같이 본다
- train 엣지의 11.5%(GATHER-SCATTER 19.6%)는 학습 시작 전에 시작한 시도에 속한다 — 그 시도의 앞부분은 라벨 없이 맥락으로만 보인다

- test 에서 새로 시작한 시도가 패턴당 277~325개 → new 묶음만 따로 평가해도 표본이 충분하다
- test 에 걸친 시도 중 학습에도 걸친 시도: GATHER-SCATTER 663/1,133 (59%) / BIPARTITE 8/497 (2%)

- 모든 패턴에서 train 엣지의 성숙도가 val·test 보다 낮다
  - 성숙도 = 엣지 시각 − 시도 시작 (일). 분할마다 패턴 엣지가 시도의 어느 단계에 몰려 있는지 
- [0, 1)일 구간이 모든 패턴에서 크다 (train 약 1,300~1,600건) → 시작한 날 바로 여러 엣지가 나오는 시도, 그리고 엣지 1~2개짜리 작은 시도가 많다
- - 최대 나이가 패턴마다 다르다: 대부분 35일 미만, BIPARTITE 21일 미만, STACK 49일 미만, GATHER-SCATTER 만 49일 이상 엣지가 있다

## 4. 시간 추이
- 정상 거래는 11/6 에 0 이 되는 게 아니라 하루 약 10^6 → 10^3 건으로 떨어지고, 이후 1/12 까지 세탁 건수와 비슷하게 줄어든다.
- UNMATCHED 는 정상 거래처럼 주 단위로 오르내리는데, 패턴 클래스는 그런 주기가 약하다 → 무패턴 세탁이 일반 거래 활동 안에서 생성된 흔적으로 보인다.(요일 피처가 UNMATCHED 와 패턴을 약간 가를 수 있다)

## 5. 분할 후보 비교
- longer_test 로 바꾸면 test 누수 후보 34.5% → 27.7%, new 30.8% → 39.8% 로 조금 나아지지만, 학습 엣지가 110,671 → 94,309 로 줄고 걸친 시도는 52.6% → 56.7% 로 늘어난다
- 개선 폭이 작고, 이진 모델과 같은 테스트 구간에서 2단계(이진 → 유형)를 끝까지 평가해야 하므로 binary_same 분할을 유지한다

## 6. 시도 안의 순서 · 진행 중 모습
- FAN-OUT·FAN-IN·BIPARTITE 는 중간 계좌가 0% — 정의대로 받고 보내는 계좌가 없다 (계산 정상 확인)

- **GATHER-SCATTER 는 두 단계 구조가 맞다**: hub 가 약 30일(29.7일) 받고, 이어서 약 29일 보낸다. 사이 간격 중앙값 −0.05일로 거의 붙어 있고, hub 첫 출금 전에 도착한 엣지가 46%

- GATHER-SCATTER 의 node_ordered 가 34% 로 낮은 건 전환 시점에서 입금·출금이 하루 이틀 겹치는 시도(55%) 때문이다. 단계가 섞인 게 아니다

- SCATTER-GATHER 는 중간 계좌의 92%가 받은 뒤 보낸다. hub 지표는 의미 없다 (in+out 최대 계좌가 보통 출발·도착 계좌라 중간 계좌가 아님, 687개 시도만 해당)

- STACK 은 층 순서가 지켜진다 (계좌 93% ordered, 층 사이 간격 중앙값 약 10일)
- RANDOM 시도의 30%는 중간 계좌가 아예 없다 → 엣지 1~2개짜리라 구조 정보가 없다

- 분할 끝 기준으로 test 에서 구조만으로는 구분할 수 없는 엣지 비율: GATHER-SCATTER → FAN-IN 33.7%, SCATTER-GATHER → FAN-OUT 26.9%, STACK → BIPARTITE 12.7%, RANDOM 13.5%·CYCLE 6.8%(경로처럼 보임)
- 구조만 보는 모델에게는 이 비율이 해당 혼동의 하한이다 → 혼동행렬 옆에 같이 둔다
- train 의 flat 비율(GATHER-SCATTER 25.0%, SCATTER-GATHER 11.1%)이 val·test 보다 낮다. 학습 구간은 8주로 길어서 구간 끝까지 단계가 넘어간 시도가 많고, val·test 는 2주라 진행 중인 시도가 많다 → 이 쌍들은 학습보다 테스트에서 더 어렵다
- 엣지 자기 시각 기준(causal)으로는 GATHER-SCATTER·SCATTER-GATHER 의 절반 가까이가 flat → 실시간으로 한 건씩 판단하면 더 어렵다

- FAN-IN·FAN-OUT·BIPARTITE 는 원래 100% flat (정상)
- RANDOM 은 30.2% 가 끝까지 중간 계좌가 생기지 않는다 → 이만큼은 구조로 RANDOM 임을 알 수 없다

## 7. 세탁만 그래프의 구조 (03_laundering_graph_check)

- BIPARTITE 엣지의 44~55%는 단독(isolated) — 양끝 계좌에 다른 세탁 엣지가 없다. STACK 도 9~19%. 나머지 패턴은 4% 이하

- UNMATCHED 는 34~41%가 단독, 약 49%는 이웃이 UNMATCHED 뿐이고, 패턴 엣지와 닿는 건 약 10%뿐 → 세탁만 그래프에서 UNMATCHED 는 패턴과 떨어진 작은 덩어리를 이룬다

- 양끝 계좌의 다른 세탁 엣지 수(other_med): FAN 계열·GATHER-SCATTER·SCATTER-GATHER 8~15 / CYCLE·RANDOM 2 / STACK·BIPARTITE·UNMATCHED 0~2 → 차수만으로도 "팬 계열 / 경로 계열 / 작은 것"이 상당히 갈린다

- 단독 엣지의 74~80%가 UNMATCHED, 12~15%가 BIPARTITE, 4~10%가 STACK → "단독이면 UNMATCHED" 가 모델이 쓸 수 있는 쉬운 신호다

- "이웃이 전부 UNMATCHED 면 96%가 UNMATCHED" 는 이웃 라벨을 알아야 쓸 수 있으므로 직접 규칙은 아니다. 다만 UNMATCHED 끼리 뭉쳐 있다는 뜻이라 크기·차수로 간접적으로 드러난다
- 한선 실험의 UNMATCHED 성능은 이 신호 덕분에 높게 나올 것이다. 8단계에서 이진 오탐 정상 거래가 이웃으로 붙으면 크게 떨어질 것으로 예상해야 한다

- 연결 요소 47,515개, 요소 크기 중앙값은 엣지 1개 (대부분 단독 엣지)
- 가장 큰 요소 하나가 엣지 91,813개(49.3%), 계좌 7.3만 개, 시도 7,943개를 담고 있다 → 거대 덩어리가 있다

- UNMATCHED 만 있는 요소 34,849개(엣지 25%), 시도 1개만 있는 요소 9,016개(7.9%), 시도 여럿이 엉킨 요소는 1,558개뿐이지만 엣지의 62%를 차지한다
- 연결 요소 단위로 분할하는 건 불가능하다 (거대 요소)

- FAN 계열·GATHER-SCATTER·SCATTER-GATHER 시도의 87~92%는 다른 시도와 같은 요소에 있고, 요소 크기 중앙값이 거대 요소(91,813) 그 자체다
- CYCLE·RANDOM 은 83% (요소 중앙값 550), BIPARTITE 64% (101), STACK 70% (165) → BIPARTITE·STACK 이 상대적으로 따로 떨어져 있다

- UNMATCHED 엣지의 57.8%는 UNMATCHED 만 있는 요소에 있다
- BIPARTITE 의 43.3%, STACK 의 33.3%는 자기 시도 하나만 있는 요소에 있다 (따로 떨어진 작은 그래프)

- 패턴 계좌 93,536개 중 82,902개(88.6%)는 시도 하나에만 쓰이지만, 10,634개는 2개 이상, 563개는 5개 이상 시도에 쓰인다 → 소수의 재사용 계좌가 시도들을 이어 거대 덩어리를 만든다

- 패턴 시도의 79~93%가 다른 시도와 계좌를 공유하고, 대부분 다른 유형의 시도와 공유한다 (77~90%)
- 41~61%는 UNMATCHED 엣지가 있는 계좌를 포함한다
- 이웃 샘플링을 하면 여러 유형이 한 서브그래프에 섞여 들어온다. 계좌 단위 신호는 오염되므로 엣지 자체의 맥락(방향, 시점, 상대 시간)이 중요하다. 엣지 단위로 예측하기로 한 선택이 맞다
- 공유 계좌 때문에 반대 방향 혼동도 생길 수 있다 (예: FAN-IN 시도의 받는 계좌가 다른 FAN-OUT 시도의 보내는 계좌 → GATHER-SCATTER 처럼 보임)
- test 의 new 시도도 계좌를 통해 학습 시도와 이어져 있을 수 있다 (아직 수치 확인 안 함)

# 시험 설계 - 유형(다중클래스) 분류

## 목적
이진 모델이 위험 후보로 올린 거래(엣지)의 유형을 맞힌다. 클래스 9개 = 패턴 8 + UNMATCHED(무패턴 세탁). 예측 단위는 엣지.
- **[상한선]** 실제 세탁 거래만 모은 그래프로 "구조로 어디까지 갈리는가"를 먼저 본다 (1~6단계)
- **[견고성]** 이진 모델이 놓친 만큼 거래를 빼도 버티는지 본다 (7단계)
- **[현실 조건]** 이진 모델 예측 양성 그래프 + 정상(오탐) 클래스로 옮긴다 (8단계)

| BIPARTITE·RANDOM 시도의 1/4 이상이 엣지 1개 | 이 엣지들은 구조로 구분 불가 → 하한 표에 포함, 금액·원장 피처로만 기대 |

## 모든 실행이 내는 표
1. **전체** : macro-F1, weighted-F1, accuracy — 검증 전체 / 검증 new / **테스트 전체 / 테스트 new / 테스트 in_train**
   - new = 그 구간에서 시작한 시도의 패턴 엣지 + 그 구간 UNMATCHED 전부 (UNMATCHED 는 시도 없음)
   - in_train = 같은 시도가 학습 구간에도 있는 패턴 엣지
   - new 와 in_train 차이가 크면 같은 시도·계좌를 외우고 있다는 신호
2. **클래스별** precision / recall / F1, 혼동행렬 (행 = 실제, 비율)
3. **혼동 쌍 vs 구조 하한** (테스트, 분할 끝 기준. 03 분석값)
   | 실제 → 예측 | 구조로 구분 불가 비율 |
   |---|---|
   | GATHER-SCATTER → FAN-IN | 33.7% |
   | SCATTER-GATHER → FAN-OUT | 26.9% |
   | STACK → BIPARTITE | 12.7% |
   | BIPARTITE → UNMATCHED | 43.9% (단독 엣지) |
   | RANDOM / CYCLE → 경로 | 13.5% / 6.8% |
   - 실제 혼동이 하한 근처면 구조 한계, 하한보다 크게 높으면 모델·피처 문제
4. **성숙도 구간별 정확도** (시도 시작 후 0~1, 1~3, 3~7, 7~14, 14~21, 21~28, 28~35, 35+ 일) — 진행 중 패턴을 얼마나 일찍 맞히나
5. **이웃 종류별 정확도** (단독 / UNMATCHED 만 / 패턴만 / 섞임) — UNMATCHED 성능이 고립 신호 덕인지
6. (보조) **시도 단위 다수결 정확도** — Alert 단위 유형을 붙일 때의 근거

## [1단계] 비그래프 기준선
- 모델: 다수 클래스, 사전분포 예측, LightGBM
- 피처: log 금액, 통화쌍, 통화 불일치, 같은 은행 여부, 결제 방식, 시간대, 요일 (절대 시각 없음)
- **결제 방식 넣은 것 / 뺀 것** 두 가지 — 생성기가 패턴마다 결제 수단을 다르게 뽑았다면 구조가 아닌 지름길
- 역할: "구조 없이 어디까지 맞히나". 이후 모든 단계의 바닥. 피처 중요도로 지름길 확인

## [2단계] 손 피처 트리 (A: 세탁 그래프 안 구조)
- LightGBM + 세탁 그래프 안 구조 피처 (거래 시각 기준 과거만)
  - 양끝 계좌의 세탁 in / out 수, 상대 계좌 수
  - 보내는 계좌가 이미 받은 적 있나, 받는 계좌가 이미 보낸 적 있나 (중간 계좌 여부)
  - 계좌의 첫 세탁 거래 이후 경과 시간, 첫 입금 → 첫 출금 간격
  - 같은 쌍 반복 수, 반대 방향 거래 존재
- **차수 피처 넣은 것 / 뺀 것** — UNMATCHED·BIPARTITE 성능이 "단독" 신호에 얼마나 기대는지
- 역할: GNN 이 넘어야 할 벤치마크 (이진의 "GFP+트리 ≈ GNN" 비교와 같은 목적)

## [3단계] GINe 상한선
- 1단계 피처(절대 시각 대신 시간대·요일) + port, 세탁만 그래프, 2층, reverse MP · ego ID (이진 01 과 같은 장치)
- 비교: 2단계 트리 대비 GNN 이 이웃 구조를 직접 봐서 얻는 몫
- 확인: 혼동 쌍이 구조 하한에 얼마나 가까운가, new / in_train 차이

## [4단계] 구조 장치 · 깊이
- 층 수 2 / 3 / 4, reverse MP · port · ego ID 하나씩 빼기
- 노리는 클래스: STACK (3층 구조), CYCLE · RANDOM (최대 13 계좌), GATHER-SCATTER (2홉 허브)
- 확인: 층을 늘릴 때 이 클래스들의 recall 이 오르고 다른 클래스가 안 떨어지나

## [5단계] 손실 가중
- 엣지 단위 클래스 가중 / 시도 균등 가중 (엣지 가중치 = 1 / 그 시도의 학습 엣지 수, UNMATCHED 는 1) / 둘 다
- 노리는 클래스: BIPARTITE · RANDOM (작은 시도), macro-F1
- 이후 단계는 가장 좋은 가중을 고정

## [6단계] 피처 사다리 (혼동 쌍 겨냥, 누적)
| 순서 | 피처 묶음 | 출처 | 노리는 혼동 |
|---|---|---|---|
| 6-1 | 순서·단계: 받는 계좌의 출금 시작 여부, 입금 시작 후 경과, 보내는 계좌의 입금 이후 경과 | A | GATHER-SCATTER ↔ FAN-IN, SCATTER-GATHER ↔ FAN-OUT |
| 6-2 | 쌍 반복·층 간격: 같은 쌍 반복, 상대 계좌가 다시 보낸 곳 수 | A | STACK ↔ BIPARTITE |
| 6-3 | 경로 회귀: 이 거래 받는 계좌에서 출발 계좌로 돌아오는 경로가 있나 (k ≤ 13) | A | CYCLE ↔ RANDOM |
| 6-4 | 원장 pair 이력 (이진 02) | B | STACK · BIPARTITE |
| 6-5 | 원장 계좌 활동 (이진 03) | B | FAN 계열, UNMATCHED (정상 활동 속 세탁) |
| 6-6 | 원장 금액 통계 (이진 04) | B | 엣지 1개짜리 시도 (구조가 없는 엣지) |
- 판단: 노린 쌍의 혼동이 구조 하한 쪽으로 줄었나. B 피처는 UNMATCHED 와 단독 BIPARTITE 를 가르는지 특히 확인

## [7단계] 누락 실험 (견고성)
- 검증·테스트 그래프에서 세탁 엣지를 recall 0.9 / 0.7 / 0.5 비율로 무작위 제거 (평가 대상 엣지는 남기고 맥락만 제거)
- 학습 때도 무작위 제거를 넣는 증강 / 안 넣음 비교
- 확인: 이진 모델이 놓친 만큼 패턴이 끊길 때 클래스별로 얼마나 떨어지나. 이진 모델의 실제 패턴별 recall (이진 report) 에 맞춘 제거 비율로도 한 번

## [8단계] 현실 조건
- 그래프 = 이진 모델 예측 양성 (운영 임계값) 거래. 엣지 수가 커지면 LinkNeighborLoader 로 전환
- 클래스 10개 = 9 + NORMAL (이진 오탐). 학습 데이터도 이진 모델 후보에서 만든다 (`유형분류선택지.md` 근거)
- 확인
  - 9클래스 부분: 6단계 최선 대비 얼마나 떨어지나, 특히 UNMATCHED (고립 신호 약화)
  - NORMAL 정밀도: 오탐을 정상으로 돌려보내는 능력
  - 이진 → 유형 전체 성능 (이진과 같은 테스트 구간)
