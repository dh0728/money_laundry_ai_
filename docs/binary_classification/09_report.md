# 09_gnn_structure 결과 (HI-Large, GINe · 트리, 시드 1, 2026-11-20)

노트북: [`09_gnn_structure.ipynb`](../../code/binary_classification/09_gnn_structure.ipynb) · 결과 파일: `code/binary_classification/results/HI-Large/gnn_structure/`

## 목적
1. **GNN 구조 장치 비교** — 피처를 공통 17종(내 버전 20열) 으로 고정하고, Multi-GNN 의 세 장치(reverse MP · port numbering · ego ID) 를 하나씩 켜 가며 얼마나 오르는지, 장치마다 노린 패턴이 오르는지 본다
2. **같은 피처 트리 비교** — 같은 20열을 트리에 주면 GNN 과 무엇이 다른지 본다 ("피처로 구조를 다 주면 그래프를 더 줄 필요가 있나")
3. **트리의 테스트 붕괴 원인** — 2 에서 트리가 검증은 멀쩡한데 테스트에서만 무너졌다. 07 의 `no_pf` 와 같은 모양이라 원인을 끝까지 따라갔다

## 한 줄 결론
- 세 장치를 켜도 전체 AP 는 시드 노이즈 범위 안이다. 노린 패턴이 따로 오르지도 않았다. 상위 0.1% 의 패턴 recall · precision 은 reverse MP 와 port 에서 조금 올랐고 ego ID 는 0 이다
- 같은 20열 트리가 테스트에서 무너진 원인은 **10-30 하루에 몰린 Reinvestment(자기 계좌 거래) 185만 건** 이었다. 이것을 빼면 트리가 GNN 과 같거나 조금 좋다
- 07 에서 "결제방식을 빼면 테스트에서 오탐이 는다" 고 본 것의 정체가 이 거래 묶음일 가능성이 크다. 결제방식 전체가 아니라 **송신 = 수신인 거래** 만 따로 다루면 될 수 있다 (다음 실험)

### 평가 지표
- **AP** : 테스트 전체, 양성 = 세탁 전부(무패턴 포함)
- **패턴 recall · precision** : 무패턴 양성은 정답도 오답도 아닌 것으로 두고 뺀다 (08 과 같은 계산). 알림 = 테스트 전체 점수 상위 0.1% (26,809건) 또는 1% (268,083건)
- **정상 오탐** : 알림 중 정상 거래 수. **비ACH 알림** : 알림 중 결제방식이 ACH 가 아닌 거래 수 (결제방식은 평가에서만 쓴다)

### 읽히는 것 (A)
1. **전체 AP 는 장치와 무관하다.** 테스트 AP 0.540 ~ 0.560. 시드 하나의 에폭 간 흔들림 안이다
2. **노린 패턴이 따로 오르지 않았다.** reverse MP → FAN-OUT 은 0.933 → 0.933. port → FAN-IN · FAN-OUT 은 +0.04 · +0.02 로 `plain` 수준을 회복한 정도. ego ID → CYCLE +0.014, SCATTER-GATHER −0.010
3. **오른 것은 `plain` 에서 약하던 네 패턴이다.** CYCLE · RANDOM · BIPARTITE · STACK 이 0.84 ~ 0.86 → 0.90 ~ 0.94. 대부분 reverse MP 단계와 port 단계에서 나왔다
4. **상위 0.1% 의 패턴 recall · precision 은 `plain` → `rev_port` 에서 +0.037 · +0.033.** ego ID 는 0 이다. 논문의 AML 표에서도 ego ID 는 거의 오르지 않았다
5. **노린 패턴은 장치 없이도 이미 잡힌다.** `plain` 의 패턴 recall 이 1% 예산에서 0.994, FAN · SCATTER/GATHER 계열은 0.1% 에서도 0.93 ~ 0.96. 누적 건수 · 서로 다른 상대 수 같은 피처가 장치가 세려던 값을 이미 주고 있다. 사다리 결과와도 맞는다 (세 장치를 다 켠 GINe: 기본 4피처 0.393 → 06 피처 0.583)
6. **전체 AP 를 막는 것은 무패턴이다.** 양성의 41% 인데 상위 0.1% 에서 0.6 ~ 3% 만 잡힌다

## 결과 C — 진단: 트리의 비ACH 알림은 어떤 거래인가
