# 패턴 룰로 alert를 생성하는 방법 실험

## 실험 설정
- 데이터 : IBM AMLworld HI-Medium. 읽은 거래 31,891,231건(09-01 ~ 09-16), 그중 룰이 보는 거래 29,331,856건 (자기 자신에게 보낸 거래 제외)
- 이력 구간 : 09-01 ~ 09-04. 룰이 과거 거래로만 쓰고 지표에는 안 넣음
- 보정 구간 : 09-05 ~ 09-07. 룰 조건을 고르는 구간
- 평가 구간 : 09-08 ~ 09-16. 고른 조건을 그대로 걸어 결과를 보는 구간 (00 의 서비스 모델 평가 구간과 같음)
- 룰은 평가 구간 끝(09-16)까지의 거래만 봄. 그 뒤 거래는 안 봄

### 지표
- 대상 패턴 : FAN-OUT, FAN-IN, GATHER-SCATTER, SCATTER-GATHER, CYCLE, RANDOM (평가 구간 세탁 9,288건)
- 지표에서 뺀 세탁 : 무패턴, STACK, BIPARTITE. 정답도 오답도 아닌 것으로 두고 뺌. 룰은 이 거래도 원장에서 그대로 봄
- 정밀도 = 고른 거래 중 세탁(패턴 종류 무관) 비율
- 재현율 = 그 룰이 노리는 패턴의 세탁 거래 중 고른 비율

### 룰 조건 후보 (전부 AND)
- ① 거래 필터 5개 : 없음 / 1천 USD 이상 / 첫거래 / 첫거래 + 1천 USD 이상 / 첫거래 + 5천 USD 이상
  - 첫거래 = 그 (송금 계좌, 수취 계좌) 쌍의 첫 거래
  - 금액은 고정 환율로 USD 로 바꿔서 비교
- ② 기간 3개 : 1일 / 3일 / 7일. 거래마다 그 시각에서 거꾸로 본 구간
- ③ 조건값 (이 값 이상이면 적중)
  - FAN-OUT · FAN-IN : 상대 계좌 수 2, 3, 4, 5, 6, 8, 10, 12, 14, 16
  - GATHER-SCATTER · SCATTER-GATHER : 계좌 수 2, 3, 4, 5, 6, 8, 10, 12
  - CYCLE : 순환 거래 수 2, 3, 4, 5, 6, 8, 10
  - RANDOM : 경로 거래 수 2, 3, 4, 5, 6, 7, 8, 10
- ④ 반복 없음 (FAN 만) : 허용 / 없음. 없음 = 기간 안 거래 수와 상대 계좌 수가 같아야 함
- 후보 수 : 1,065개

### 고르는 방법
- 룰마다 보정 구간에서 F1 이 가장 높은 후보 하나를 고르고, 평가 구간에서는 조건을 바꾸지 않음

### 고정한 값
- 경로형(CYCLE · RANDOM) : 이어지는 두 거래의 금액 비 0.8 ~ 1.25, 최대 12건까지 따라감
- 바쁜 계좌 : 72시간 안 같은 방향 거래가 512건을 넘는 계좌. 룰의 대상도 경유도 되지 않음

### 패턴별 핵심 (HI-Medium, 환전 조건 넣기 전)

- **FAN-IN** : 정상 계좌도 새 상대 여럿에게서 큰돈을 받아서 구분이 안 됨. 필터를 끝까지 올려도(첫거래 + 5천) 정밀도 10%, 조건값을 올려도 그대로. 룰 6종 오탐 26,794건 중 25,558건이 여기서 나옴
- **FAN-OUT** : 첫거래와 금액 하한을 같이 걸어야 정상이 빠짐 (하나만 걸면 0.6 ~ 2.0%, 둘 다 걸면 96.2%). 놓치는 건 작은 시도(5건 이하)와 구간 끝
- **GATHER-SCATTER** : 정상에 거의 없는 모양이라 정확함(99.1%). 대신 패턴이 7일보다 길어서(시도 길이 중앙값 9.5일) 큰 시도의 일부만 잡음. 놓친 것의 54% 는 FAN-IN · FAN-OUT 룰이 대신 잡음
- **SCATTER-GATHER** : 모양 자체가 정상에 드묾. 경유 계좌 4개 이상이 핵심 (2개 23.0% → 4개 90.5%). 기간이 7일은 돼야 함 (3일이면 재현율 9.0%). 작은 시도(9건 이하)를 놓침
- **CYCLE** : 닫힌 순환만 잡아서 시도 단위로 전부 아니면 전무 (39.0% 전부 잡음, 58.8% 하나도 못 잡음). 닫히기 전 순환과 2건짜리 왕복은 못 잡음. 구간 끝으로 갈수록 재현율이 가장 크게 떨어짐 (68% → 16%)
- **RANDOM** : 금액이 비슷하게 이어지는 경로는 정상끼리도 우연히 생김. 기간을 늘리면 재현율은 오르고 정밀도가 무너짐 (3일 83.6% / 36.9% → 7일 59.6% / 57.2%)

### 공통으로 읽히는 것

- 정상에 드문 모양(G-S, S-G, CYCLE)은 필터가 약해도 정확하고, 정상에도 흔한 모양(FAN-IN, RANDOM)은 조건을 올려도 정밀도가 안 나옴
- 재현율을 깎는 원인은 세 가지: 작은 시도, 7일보다 긴 패턴, 구간 끝에서 아직 완성 안 된 시도
- 한 룰이 놓친 거래를 다른 룰이 잡는 경우가 많음 (G-S 는 FAN 룰이, CYCLE 앞부분은 RANDOM 룰이)


## 실험 2. 환전 여부 추가

### 배경
- FAN-IN 같은 경우 금액의 크기로는 정상과 구분이 힘들었음
- 근데 확인 결과 FAN-IN은 통화 환전 이후 그 금액만큼 여러 계좌로 흩어지는 경향이 있는 것을 파악하고 그 조건을 넣어서 확인
- 다른 패턴들도 동일하게 환전 조건을 추가했을 때 지표 변화를 측정
- 이때 and, or 둘다 넣고 수치를 비교
