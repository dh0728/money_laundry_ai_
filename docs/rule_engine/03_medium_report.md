# 패턴 룰로 alert를 생성하는 방법 실험

논문의 패턴 정의
패턴	논문 정의
FAN-OUT	한 계좌 v에서 서로 다른 계좌 k개 이상(k ≥ 2)으로 나가는 간선
FAN-IN	반대 방향으로, 서로 다른 계좌 2개 이상에서 v 하나로 들어오는 간선
GATHER-SCATTER	같은 계좌에 대한 FAN-IN과 FAN-OUT의 결합
SCATTER-GATHER	출발 계좌의 FAN-OUT과 도착 계좌의 FAN-IN이 같은 중간 계좌 집합을 공유하는 구조. 그림 예시는 중간 계좌 4개지만 최소 개수는 명시 안 돼 있어
CYCLE	출발 계좌로 되돌아오고 다른 계좌는 최대 한 번씩만 지나는 단순 순환
RANDOM	순환과 비슷하지만 원래 계좌로 돌아오지 않는, 세탁자가 통제하는 계좌들 사이의 랜덤 워크
BIPARTITE	입력 계좌 집합에서 출력 계좌 집합으로 자금이 이동
STACK	BIPARTITE에 층을 하나 더 얹은 구조

## 실험 설정
- 데이터 : IBM AMLworld HI-Medium. 읽은 거래 31,891,231건(09-01 ~ 09-16), 그중 룰이 보는 거래 29,331,856건 (자기 자신에게 보낸 거래 제외)
- 이력 구간 : 09-01 ~ 09-04. 룰이 과거 거래로만 쓰고 지표에는 안 넣음
- 보정 구간 : 09-05 ~ 09-07. 룰 조건을 고르는 구간
- 평가 구간 : 09-08 ~ 09-16. 고른 조건을 그대로 걸어 결과를 보는 구간 (00 의 서비스 모델 평가 구간과 같음)
- 룰은 평가 구간 끝(09-16)까지의 거래만 봄. 그 뒤 거래는 안 봄

### 지표
- 대상 패턴 : FAN-OUT, FAN-IN, GATHER-SCATTER, SCATTER-GATHER, CYCLE, RANDOM (평가 구간 세탁 9,288건)
- 지표에서 뺀 세탁 : 무패턴, STACK, BIPARTITE. 정답도 오답도 아닌 것으로 두고 뺌. 룰은 이 거래도 원장에서 그대로 봄
- 정밀도 = 고른 거래 중 세탁(패턴 종류 무관) 비율
- 재현율 = 그 룰이 노리는 패턴의 세탁 거래 중 고른 비율

### 룰 조건 후보 (전부 AND)
- ① 거래 필터 5개 : 없음 / 1천 USD 이상 / 첫거래 / 첫거래 + 1천 USD 이상 / 첫거래 + 5천 USD 이상
  - 첫거래 = 그 (송금 계좌, 수취 계좌) 쌍의 첫 거래
  - 금액은 고정 환율로 USD 로 바꿔서 비교
- ② 기간 3개 : 1일 / 3일 / 7일. 거래마다 그 시각에서 거꾸로 본 구간
- ③ 조건값 (이 값 이상이면 적중)
  - FAN-OUT · FAN-IN : 상대 계좌 수 2, 3, 4, 5, 6, 8, 10, 12, 14, 16
  - GATHER-SCATTER · SCATTER-GATHER : 계좌 수 2, 3, 4, 5, 6, 8, 10, 12
  - CYCLE : 순환 거래 수 2, 3, 4, 5, 6, 8, 10
  - RANDOM : 경로 거래 수 2, 3, 4, 5, 6, 7, 8, 10
- ④ 반복 없음 (FAN 만) : 허용 / 없음. 없음 = 기간 안 거래 수와 상대 계좌 수가 같아야 함
- 후보 수 : 1,065개

- 바쁜 계좌 : 72시간 안 같은 방향 거래가 512건을 넘는 계좌. 룰의 대상도 경유도 되지 않음

### 패턴별 핵심 (HI-Medium, 환전 조건 넣기 전)

- **FAN-IN** : 정상 계좌도 새 상대 여럿에게서 큰돈을 받아서 구분이 안 됨. 필터를 끝까지 올려도(첫거래 + 5천) 정밀도 10%, 조건값을 올려도 그대로. 룰 6종 오탐 26,794건 중 25,558건이 여기서 나옴
- **FAN-OUT** : 첫거래와 금액 하한을 같이 걸어야 정상이 빠짐 (하나만 걸면 0.6 ~ 2.0%, 둘 다 걸면 96.2%). 놓치는 건 작은 시도(5건 이하)와 구간 끝
- **GATHER-SCATTER** : 정상에 거의 없는 모양이라 정확함(99.1%). 대신 패턴이 7일보다 길어서(시도 길이 중앙값 9.5일) 큰 시도의 일부만 잡음. 놓친 것의 54% 는 FAN-IN · FAN-OUT 룰이 대신 잡음
- **SCATTER-GATHER** : 모양 자체가 정상에 드묾. 경유 계좌 4개 이상이 핵심 (2개 23.0% → 4개 90.5%). 기간이 7일은 돼야 함 (3일이면 재현율 9.0%). 작은 시도(9건 이하)를 놓침
- **CYCLE** : 닫힌 순환만 잡아서 시도 단위로 전부 아니면 전무 (39.0% 전부 잡음, 58.8% 하나도 못 잡음). 닫히기 전 순환과 2건짜리 왕복은 못 잡음. 구간 끝으로 갈수록 재현율이 가장 크게 떨어짐 (68% → 16%)
- **RANDOM** : 금액이 비슷하게 이어지는 경로는 정상끼리도 우연히 생김. 기간을 늘리면 재현율은 오르고 정밀도가 무너짐 (3일 83.6% / 36.9% → 7일 59.6% / 57.2%)

### 공통으로 읽히는 것

- 정상에 드문 모양(G-S, S-G, CYCLE)은 필터가 약해도 정확하고, 정상에도 흔한 모양(FAN-IN, RANDOM)은 조건을 올려도 정밀도가 안 나옴
- 재현율을 깎는 원인은 세 가지: 작은 시도, 7일보다 긴 패턴, 구간 끝에서 아직 완성 안 된 시도
- 한 룰이 놓친 거래를 다른 룰이 잡는 경우가 많음 (G-S 는 FAN 룰이, CYCLE 앞부분은 RANDOM 룰이)


## 실험 2. 환전 여부 추가

### 배경
- FAN-IN 은 금액 크기와 첫거래 여부로는 정상과 구분이 안 됐음 (정밀도 10.2%)
- 원장을 확인해 보니 세탁 송금은 보내는 계좌가 자기 계좌 안에서 환전한 직후 그 금액을 보내는 경우가 많았음
  - HI-Medium 에서 이런 송금은 정상 거래의 1.6%, 6종 패턴 세탁의 53 ~ 57%
- 이 조건을 FAN-IN 뿐 아니라 6개 패턴 전부에 넣어 보고 지표 변화를 측정
- AND 로 넣는 방식과 OR 로 넣는 방식을 둘 다 비교

### 환전 조건의 정의
남에게 보낸 거래 중 아래를 모두 만족하는 거래를 "환전 직후 송금" 으로 봄
- 같은 계좌가 같은 시각(분)에 자기 계좌 안에서 환전함 (송금 계좌 = 수취 계좌, 보낸 통화 ≠ 받은 통화)
- 환전해 받은 통화가 이 송금의 통화와 같음
- 보낸 금액 ÷ 환전해 받은 금액이 0.8 ~ 1.25

### 환전 조건을 넣는 방식별 결과 (HI-Medium, 평가 구간 09-08 ~ 09-16)

- 값 = 정밀도 / 재현율. 16일 뒤로 이어지는 시도까지 포함
- 기존 조건 : 환전 조건 없이 고른 룰
- 환전 AND : 환전 직후 송금만 세는 룰
- 필터 안 OR : 첫 거래이거나 환전 직후 송금이면 세는 룰
- 룰 단위 OR : 기존 조건으로 고른 거래 ∪ 환전 AND 로 고른 거래

| 룰 | 기존 조건 | 환전 AND | 필터 안 OR | 룰 단위 OR |
|---|---:|---:|---:|---:|
| FAN-OUT | 96.2% / 70.8% | 99.4% / 46.4% | 95.9% / 69.0% | 96.1% / 76.5% |
| FAN-IN | 10.2% / 69.2% | **99.7% / 55.2%** | 10.4% / 68.7% | 11.5% / 81.5% |
| GATHER-SCATTER | 99.1% / 49.2% | 100% / 34.9% | 94.2% / 41.7% | 99.3% / 57.6% |
| SCATTER-GATHER | 90.5% / 68.2% | 99.9% / 32.9% | 92.3% / 59.5% | 90.8% / 71.3% |
| CYCLE | 85.9% / 46.0% | 98.0% / 3.2% | 75.1% / 19.6% | 86.1% / 47.0% |
| RANDOM | 59.6% / 57.2% | 78.0% / 42.9% | **89.7% / 55.4%** | 65.6% / 68.8% |

- 환전 AND 는 정밀도를 98 ~ 100% 로 올리지만, 환전 직후 송금이 세탁의 53 ~ 57% 뿐이라 재현율이 그 근처로 묶임
- FAN-IN 은 기존 정밀도가 10% 라 그 교환이 이득 → **환전 AND 를 씀**
- 나머지는 기존 정밀도가 이미 86 ~ 99% 라 재현율만 깎임 → 환전 AND 를 쓰지 않음
- RANDOM 은 **필터 안 OR 를 씀**. 첫거래 필터로 끊기던 경로를 환전이 다시 이어 줘서 재현율은 비슷하고 정밀도가 59.6% → 89.7% 로 오름
- CYCLE 은 경로의 모든 거래가 환전 직후 송금이어야 해서 환전 AND 로는 거의 못 잡음 (3.2%)

  - CYCLE : 자기 룰은 6.1% 뿐이고 RANDOM 룰이 44.1% 를 잡음. 닫히기 전 순환은 RANDOM 모양
- 그래서 자기 룰 재현율은 크게 떨어져도 합집합은 덜 떨어짐 (G-S 80.8% → 73.6%, S-G 85.4% → 75.1%)
